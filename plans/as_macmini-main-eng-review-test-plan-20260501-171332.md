This test plan is consumed by `/qa` and `/qa-only` as primary input. It captures **what to test and where** for V1 PlantCare.

## Frameworks

- **Mobile (Expo / RN):** jest + jest-expo + @testing-library/react-native (unit, component)
- **Backend (Hono / Cloudflare Workers):** vitest + @cloudflare/vitest-pool-workers (unit, integration)
- **E2E (mobile):** Maestro (YAML flows)
- **LLM evals:** vitest snapshot tests in backend repo, 10 fixture images per endpoint

## Affected Pages/Screens

- **A-1 Plants list** — empty state (Day 1), populated state, status chips render, FAB tap, FAB long-press popover, scroll
- **A-2 Plant detail** — hero photo loads, status chip type matches `useWateringEngine`, 7-day ledger renders correctly, Mark watered persists, Add note bottom sheet opens, Diagnose button routes to A-5 in diagnose mode, photo timeline pads correctly
- **A-3 Camera result (diagnose)** — success path, low-confidence path, timeout error, layer-1 reject, second-opinion in flight, save to plant
- **A-4 Add plant** — happy path, 0% match falls to manual species picker, network failure queues, nickname + location fields persist
- **A-5 Camera capture** — first-launch pre-prompt, iOS permission grant, permission denied tan card with deep link to Settings, mode toggle (Identify ↔ Diagnose), shutter capture
- **A-6 Weekly review (Sundays)** — Sunday letter card appears on Sundays, dismisses on Got it, per-plant ledger summary renders
- **NonPhoneRedirect** — iPad and Web users see "iPhone-only for now" card

## Key Interactions to Verify

- Mark watered → 7-day ledger updates immediately + watering_events row inserted
- FAB long-press → popover with "Add a plant" + "Quick diagnose" → quick-diagnose path doesn't save plant or diagnosis to garden
- Add note chip ("Just repotted") → consult API → revised watering rec appears inline above buttons
- Diagnose loading → 0-8s "Looking closely…" / 8-20s "Almost there…" / 20s+ "Trying a more careful look…" copy switches at the time buckets
- Diagnose with reduce-motion enabled → no pulsing animation, static text
- Identify mode at A-5 → /api/identify; Diagnose mode → /api/diagnose
- Status chip metaphor: water = pale blue droplet, skip = sage leaf, soil = warm tan hand
- Dynamic type at 310% scale → Fraunces headlines + Inter labels scale, layout doesn't break
- iPad / Web → NonPhoneRedirect card with deep-link CTA (do NOT render the phone screens)
- Dark mode (system-driven via useColorScheme) → all 5 screens render with Midnight Conservatory tokens, status fills unchanged in hue
- Sunday Letter card appears only on Sundays (or first launch after >7 days since last review)
- Tap "Mark watered" with no network → still works (local-first)

## Edge Cases

- Plant with 47-character nickname (Fraunces italic should truncate or wrap, not blow up the row)
- Plant with `species_unknown` (watering rules disabled, badge shows "—" or hidden)
- Day 1: 0 plants → EmptyGardenWelcome card, FAB hidden until 1+ plants exist
- Just-added plant: 0 watering events → 7 outline droplets + "No watering recorded yet" hint
- 100+ photos in plant timeline → renders only first 4 thumbnails, "View all" affordance (or use FlatList virtualization)
- Watering rules at the boundary: exactly `adjusted_target` days → "water today"; `adjusted_target - 1` → "check soil"
- Timezone change overnight (DST or travel) → watering count uses `(now - last_watered_at) / 86400000` (millisecond math), NOT calendar days; verify in unit test
- Camera permission denied → tan card stays until user toggles in Settings; "Open Settings" deep links to `app-settings:` (iOS) or app-settings package URI (Android)
- Diagnose photo > OpenRouter request limit → photo compression happens client-side BEFORE upload; verify resulting image is < 1MB
- Layer-1 classifier rejects on cat photo → A-3 shows "Hmm, I don't see a plant here" tan card, not Spider mites
- Identify confidence at exactly 70 → router does NOT escalate (threshold is `< 70`)
- Identify confidence at 69 + escalation budget exhausted → return free model's answer with `source: 'free'` and surface low-confidence UX in app
- Sync queue: 5 failed attempts → status=failed, banner shows "Tap to retry" → tap re-queues with attempt_count=0
- Sync queue: item created 8 days ago → sweeper marks expired, never re-runs
- All 7 days watered in ledger → 7 filled droplets, no outline
- All 7 days skipped → 7 outline droplets

## Critical Paths (E2E — Maestro)

These are the must-not-break flows. Every refactor runs these before merge.

1. **Day 1 onboarding** — clean install → empty garden → tap "Add my first plant" → camera capture (granted) → identify mode → photo of monstera → confirm Fiddle Leaf Fig override → "Add to garden" → Plants list shows 1 row.
2. **Daily glance loop** — open app → see "Steve · WATER TODAY" → tap card → A-2 detail → tap "Mark watered" → ledger droplet for today fills → back to list → chip flips to SKIP.
3. **Rescue moment (hero)** — A-2 → tap Diagnose → camera in diagnose mode → capture sick leaf → loading copy pulses → "Spider mites" result lands → tap "Save to Steve" → back to A-2 with diagnose timeline showing the new entry.
4. **Quick diagnose** — long-press FAB on A-1 → popover → tap "Quick diagnose" → A-5 in diagnose mode → capture → A-3 result → "Done" CTA dismisses to A-1 with NO new plant saved and NO diagnose saved.
5. **Offline diagnose recovery** — airplane mode on → A-2 → Diagnose → capture → tan banner "Diagnose queued — will run when online" → airplane mode off → drainer runs → diagnose result lands as new entry in plant's diagnose timeline.
6. **Camera permission deny + recover** — fresh install → first camera trigger → deny iOS prompt → tan card "Camera disabled" → tap "Open Settings" → iOS Settings opens to PlantCare entry.
7. **Add note + LLM consult** — A-2 → tap Add note → bottom sheet → tap "Just repotted" chip → tap "Save & ask" → loading → revised watering rec appears inline.
8. **Sunday weekly review** — set device date to Sunday → open app → SundayLetterCard at top of A-1 → tap → A-6 weekly review with hero illustration + per-plant ledger → "Got it" → dismisses, doesn't reappear until next Sunday.

## LLM evals (backend, vitest snapshot)

- **/api/identify** — 10 fixture images: 6 healthy (monstera, snake, fiddle, pothos, ZZ, spider) + 2 partial-occlusion + 1 low-light + 1 cat photo (should be rejected by Layer-5). Assert `species_slug` matches expected; `confidence` within ±10 of baseline.
- **/api/diagnose** — 10 fixture images: 7 sick (spider mites, mealybugs, root rot, sunburn, overwatering, underwatering, leaf scorch) + 2 healthy controls + 1 cat photo. Assert `disease_slug` matches; `severity` within ±1 step.
- **/api/consult** — 5 fixture text prompts: "I just repotted it", "leaves drooping", "moved to brighter spot", "browning leaf tips", "a question about my dog" (Layer-1 reject). Assert response category (`watering_revision` | `general_advice` | `rejected_off_topic`).
- **/api/review** — 1 fixture watering history (mixed, 7 days, 6 plants). Assert response includes per-plant observation lines + summary paragraph length within 100-400 chars.

## Test execution targets

- Unit + component tests run on every push (CI). Target: full suite < 30 sec.
- E2E (Maestro) runs nightly + on every push to main. Target: 8 flows complete < 5 min.
- LLM evals run on every change to backend prompt files (`apps/backend/src/prompts/*`). Target: full suite < 60 sec.
- Coverage target: 80% line coverage on `src/hooks/`, `src/sync/`, `src/api/`, `apps/backend/src/`. UI primitives are component-tested, not coverage-tracked.

## Regression — CRITICAL

The timezone-change-overnight bug in `useWateringEngine` is flagged as the most likely silent regression. Add a dedicated unit test that simulates DST forward/backward and a flight across the international date line. Verify watering count uses millisecond math, not calendar-day math. **No skipping this test.**
